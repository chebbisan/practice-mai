# 1. Направленные свойства ФАР

Фазированная антенная решётка (ФАР) представляет собой систему излучателей, расположенных в пространстве по определённому закону, диаграмма направленности (ДН) которой формируется путём управления амплитудно-фазовым распределением (АФР) токов возбуждения элементов [1]. Ключевой характеристикой ФАР является её ДН — зависимость напряжённости поля от направления наблюдения. Для численного анализа направленных свойств ФАР в рамках настоящей работы разработан программный комплекс, реализующий расчёт ДН и коэффициента направленного действия (КНД) для антенных решёток произвольной конфигурации.

Вычислительное ядро реализовано на языке C++ в виде разделяемой библиотеки, обеспечивающей высокую производительность при расчёте множителя решётки. Интерфейс пользователя и визуализация результатов выполнены на Python с использованием библиотек NumPy и Matplotlib. Взаимодействие между слоями осуществляется через механизм ctypes. Параметры решётки (координаты элементов, амплитуды возбуждения) задаются в формате CSV, что позволяет исследовать решётки произвольной геометрии без модификации исходного кода.

## 1.1 Автоматизация расчёта ДН ФАР

### 1.1.1 Линейная эквидистантная равноамплитудная решётка

Рассмотрим линейную антенную решётку из $N$ идентичных излучателей, расположенных вдоль оси $x$ с постоянным шагом $d$. При равноамплитудном синфазном возбуждении нормированный множитель решётки определяется выражением [1]:

$$f_n(\Theta) = \frac{\sin\left(\frac{\pi N d \sin\Theta}{\lambda}\right)}{N \sin\left(\frac{\pi d \sin\Theta}{\lambda}\right)},$$

где $\Theta$ — угол, отсчитываемый от нормали к решётке, $\lambda$ — длина волны.

Данное аналитическое выражение имеет ряд важных свойств:
- главный максимум при $\Theta = 0°$ (направление нормали);
- нули при $\sin\Theta = p\lambda/(Nd)$, $p = \pm 1, \pm 2, \ldots$;
- уровень первого бокового лепестка $\approx -13{,}26$ дБ (при $N \geq 12$);
- ширина главного лепестка по уровню половинной мощности $2\Theta_{0{,}7} \approx 51° \cdot \lambda/(Nd)$.

Для обеспечения единственности главного максимума в пределах видимой области ($-90° \leq \Theta \leq 90°$) необходимо выполнение условия $d < \lambda$, на практике обычно выбирают $d \leq \lambda/2$.

При электронном сканировании луча на угол $\Theta_m$ между соседними элементами вводится линейный фазовый сдвиг $\psi_1$, и множитель решётки принимает вид:

$$f_n(\Theta) = \frac{\sin\left(\frac{N(kd\sin\Theta + \psi_1)}{2}\right)}{N\sin\left(\frac{kd\sin\Theta + \psi_1}{2}\right)},$$

где $k = 2\pi/\lambda$ — волновое число. Направление главного максимума определяется из условия $\sin\Theta_m = -\psi_1/(kd)$. Для обеспечения единственности сканируемого луча шаг решётки должен удовлетворять условию [1]:

$$d < \frac{\lambda}{1 + \sin\Theta_m}.$$

В разработанном программном комплексе данная формула используется для автоматического выбора шага решётки при заданном максимальном угле сканирования.

Для верификации реализации выполнено сравнение результатов численного расчёта с аналитической формулой множителя решётки. Для равноамплитудной решётки с $d = \lambda/2$ и изотропными элементами при $N = 4, 8, 16$ максимальное расхождение составило $\sim 10^{-15}$, что соответствует машинной точности арифметики двойной точности. Положения нулей ДН и уровень первого бокового лепестка также совпадают с аналитическими значениями (таблица 1.1).

### 1.1.2 Линейная решётка с произвольным расположением элементов

В общем случае элементы линейной антенной решётки могут располагаться неэквидистантно и иметь различные амплитуды возбуждения. Множитель такой решётки вычисляется по формуле:

$$F(\Theta) = \frac{1}{N}\sum_{n=0}^{N-1} f_n \cdot \exp\left(-jk x_n \sin\Theta\right),$$

где $f_n$ — комплексная амплитуда возбуждения $n$-го элемента, $x_n$ — его координата вдоль оси решётки. Данная формула реализована в функции `Calculate1DAntennaArray` вычислительного ядра на C++.

Полная ДН решётки определяется как произведение множителя решётки на ДН одиночного элемента $f_1(\Theta)$:

$$F_{\Sigma}(\Theta) = f_1(\Theta) \cdot F(\Theta).$$

В программном комплексе реализованы три варианта ДН элемента:
- изотропный: $f_1(\Theta) = 1$;
- косинусный: $f_1(\Theta) = |\cos\Theta|$;
- полуволновый вибратор: $f_1(\Theta) = \left|\frac{\cos(\frac{\pi}{2}\sin\Theta)}{\cos\Theta}\right|$.

Параметры решётки загружаются из CSV-файла с колонками `x_m, amplitude_db`, что позволяет задавать произвольное расположение элементов и произвольное амплитудное распределение. Амплитуды задаются в децибелах и преобразуются в линейный масштаб: $A = 10^{A_{\text{дБ}}/20}$.

### 1.1.3 Плоская АР с произвольным расположением элементов

Для плоской антенной решётки с $N$ элементами, расположенными в плоскости $xOy$ с координатами $(x_n, y_n)$, множитель решётки является функцией двух углов $\Theta$ и $\varphi$ [2]:

$$F(\Theta, \varphi) = \frac{1}{N}\sum_{n=0}^{N-1} f_n \cdot \exp\left(-jk(x_n \sin\Theta\cos\varphi + y_n \sin\Theta\sin\varphi)\right),$$

где $\Theta$ — угол от нормали к плоскости решётки, $\varphi$ — азимутальный угол. Данная формула реализована в функции `Calculate2DAntennaArray` и совпадает с формулой (3) из [2].

Параметры плоской решётки задаются в CSV-файле с тремя колонками: `x_m, y_m, amplitude_db`. Это позволяет исследовать решётки произвольной геометрии: прямоугольные, гексагональные, с произвольной формой границы раскрыва.

Визуализация ДН плоской решётки выполняется в трёх формах:
- круговая тепловая карта в проекции $(u, v) = (\sin\Theta\cos\varphi, \sin\Theta\sin\varphi)$;
- сечение плоскостью $\varphi = 0°$ (плоскость $xOz$, вдоль длинной стороны раскрыва);
- сечение плоскостью $\varphi = 90°$ (плоскость $yOz$, вдоль короткой стороны раскрыва).

В качестве примера выполнен расчёт ДН прямоугольной решётки $40 \times 12$ элементов с шагом $d = 0{,}5\lambda$ при частоте $f = 3$ ГГц (параметры из [2]). На рисунке 1.1 представлены сечения ДН в главных плоскостях. Ширина главного лепестка составляет $\approx 2{,}5°$ в плоскости $\varphi = 0°$ (40 элементов) и $\approx 8°$ в плоскости $\varphi = 90°$ (12 элементов), что согласуется с формулой $2\Theta_{0{,}7} \approx 51° \cdot \lambda/(Nd)$.

### 1.1.4 Пространственная (объёмная) АР с произвольным расположением элементов

Для пространственной антенной решётки элементы располагаются в трёхмерном пространстве с координатами $(x_n, y_n, z_n)$. Множитель такой решётки обобщает формулу плоской решётки добавлением фазового вклада вдоль оси $z$ [1, раздел 12.4, формула 12.9]:

$$F(\Theta, \varphi) = \frac{1}{N}\sum_{n=0}^{N-1} f_n \cdot \exp\left(-jk(x_n \sin\Theta\cos\varphi + y_n \sin\Theta\sin\varphi + z_n \cos\Theta)\right).$$

Физический смысл дополнительного слагаемого $z_n \cos\Theta$: проекция вектора наблюдения на ось $z$ (нормаль к плоскости раскрыва) определяется множителем $\cos\Theta$, а не $\sin\Theta$, поскольку угол $\Theta$ отсчитывается от нормали. Для плоской решётки ($z_n = 0$ для всех $n$) формула вырождается в выражение для 2D случая (раздел 1.1.3).

Данная формула реализована в функции `Calculate3DAntennaArray` вычислительного ядра на C++. Расчёт КНД и визуализация выполняются по тем же формулам, что и для плоской решётки (раздел 1.2), поскольку ДН пространственной решётки также является функцией двух угловых переменных $(\Theta, \varphi)$.

Параметры пространственной решётки задаются в CSV-файле с четырьмя колонками: `x_m, y_m, z_m, amplitude_db`. Загрузчик CSV автоматически определяет размерность решётки по числу колонок (2 — 1D, 3 — 2D, 4 — 3D).

Для верификации реализации выполнены следующие тесты:
- **Вырождение в 2D**: при $z_n = 0$ для всех элементов результат `Calculate3DAntennaArray` совпадает с `Calculate2DAntennaArray` с точностью до $\sim 10^{-12}$ (машинная точность);
- **Один элемент**: $D_0 \approx 2{,}0$, что соответствует аналитическому значению для изотропного излучателя;
- **Рост КНД**: добавление слоёв по оси $z$ увеличивает КНД по сравнению с плоской решёткой.

## 1.2 Расчёт КНД антенных решёток

Коэффициент направленного действия (КНД) характеризует степень концентрации излучения антенны в заданном направлении. В направлении максимума излучения КНД определяется выражением [1]:

$$D_0 = \frac{4\pi}{\displaystyle\int_0^{2\pi}d\varphi\int_{-\pi/2}^{\pi/2} F^2(\Theta,\varphi)\cos\Theta\,d\Theta},$$

где $F(\Theta,\varphi)$ — нормированная ДН ($F_{\max} = 1$).

Для антенн с осевой симметрией (линейная решётка, ДН не зависит от $\varphi$) формула упрощается:

$$D_0 = \frac{2}{\displaystyle\int_{-\pi/2}^{\pi/2} F^2(\Theta)\cos\Theta\,d\Theta}.$$

Интеграл вычисляется методом трапеций. Для линейной решётки с $d = \lambda/2$ и изотропными элементами КНД точно равен $D_0 = N$ [3], что подтверждено расчётами (таблица 1.1).

Для плоской решётки интегрирование выполняется по двум переменным. Сначала для каждого значения $\varphi_j$ вычисляется внутренний интеграл по $\Theta$, затем результат интегрируется по $\varphi$.

### 1.2.1 Анализ причин превосходства NumPy над C++

Результаты тестирования показали, что **векторизованная реализация на NumPy является самым быстрым подходом**, опережая даже чистый C++ в 2,7–3,4 раза. Данный результат, на первый взгляд, является неожиданным, поскольку C++ — компилируемый язык, традиционно ассоциируемый с высокой производительностью. Ниже приведён анализ причин.

**1. Различие в модели вычислений.** Вычисление множителя решётки в C++ реализовано как явный тройной цикл: для каждого угла $(\Theta_i, \varphi_j)$ выполняется суммирование по $N$ элементам с вызовами тригонометрических функций (`sin`, `cos`, `exp`). Общее число итераций составляет $O(N \cdot n_\Theta \cdot n_\varphi)$, при этом каждая итерация является скалярной операцией.

Реализация на NumPy, напротив, формулирует ту же задачу как серию операций над матрицами:
```python
st_cp = np.outer(np.sin(theta), np.cos(phi))   # [n_theta × n_phi]
for n in range(N):
    af += a[n] * np.exp(-1j * k * (x[n]*st_cp + y[n]*st_sp))
```
Здесь внутренний цикл по угловым точкам заменён вызовом `np.exp` над матрицей размера $n_\Theta \times n_\varphi$, который выполняется в оптимизированном скомпилированном коде библиотеки NumPy.

**2. SIMD-векторизация.** Библиотека NumPy использует оптимизированные реализации математических функций (Intel MKL, OpenBLAS), которые применяют SIMD-инструкции процессора (AVX, AVX2, AVX-512) для одновременной обработки нескольких элементов массива. Функция `np.exp` для массива из $10^4$ комплексных чисел обрабатывает 4–8 элементов за такт, тогда как скалярный `std::exp` в C++ обрабатывает один элемент за вызов.

**3. Кэш-локальность.** NumPy оперирует непрерывными массивами в формате C-contiguous, что обеспечивает последовательный доступ к памяти и эффективное использование кэша процессора. В C++ реализации доступ к структурам `complex_t` и вычисление фазы для каждого элемента решётки приводит к менее предсказуемому паттерну обращений к памяти.

**4. Отсутствие оптимизаций компиляции.** C++ код скомпилирован с настройками CMake по умолчанию (без флагов `-O2`/`-O3` и `-march=native`), что не позволяет компилятору применить автоматическую векторизацию циклов и оптимизации для конкретной архитектуры процессора. При включении данных флагов разрыв в производительности может сократиться, однако, как показывает практика, оптимизированные библиотеки линейной алгебры (BLAS) всё равно превосходят автовекторизацию компилятора для данного класса задач.

### 1.2.2 Проблемы проектирования гибридной архитектуры

При разработке программного комплекса был выявлен ряд проблем, связанных с гибридной архитектурой C++ + Python.

**1. Накладные расходы на маршалинг данных.** Интерфейс ctypes требует преобразования Python-объектов в C-типы (`list_to_c_double_array`, `list_to_c_complex_array`) перед каждым вызовом и обратного преобразования результатов. Для гибридного подхода (C++ + NumPy) эти преобразования выполняются дважды — при передаче входных данных и при извлечении результата. Бенчмарки показали, что **гибридный подход (C++ + NumPy) работает в 1,5–2,3 раза медленнее, чем чистый C++** (таблица 1.3), при том что единственная разница — маршалинг данных через ctypes.

**2. Управление памятью.** C++ функции `Calculate1DAntennaArray`, `Calculate2DAntennaArray` и `Calculate3DAntennaArray` возвращают динамически выделенные массивы, которые должны быть явно освобождены вызовом `FreeComplexArr` на стороне Python. Забытый вызов `Free` приводит к утечке памяти, которая не обнаруживается стандартными средствами Python (сборщик мусора не управляет C-памятью). Для решения данной проблемы были разработаны функции полного пайплайна (`FullPipeline1D`/`2D`/`3D`), которые выделяют и освобождают всю промежуточную память внутри C++ и возвращают только скалярный результат ($D_0$).

**3. Дублирование кода.** Поддержка четырёх реализаций одного и того же алгоритма (Pure Python, NumPy, C++ + NumPy, Pure C++) создаёт проблему сопровождения: при изменении формулы расчёта необходимо обновлять все четыре варианта. На практике эта проблема возникла при добавлении 3D расчёта — формулу множителя решётки потребовалось реализовать в `antenna_array.cpp` (2 функции: `Calculate3DAntennaArray` и `FullPipeline3D`), в `calc_3d.py` (NumPy), и в `test_benchmark_3d.py` (Pure Python).

**4. Выбор основного метода расчёта.** По результатам бенчмарков принято решение использовать **NumPy как основной метод расчёта** в модулях `calc_2d.py` и `calc_3d.py`, отказавшись от вызовов C++ библиотеки через ctypes. Корректность NumPy-реализации подтверждена сравнением с C++: максимальное расхождение множителя решётки составило $\sim 10^{-15}$ для 2D и $\sim 10^{-15}$ для 3D, что соответствует машинной точности арифметики двойной точности. C++ библиотека сохранена для бенчмарков и для операций с нестандартными структурами данных.

## 1.3 Выводы

1. Разработан программный комплекс для расчёта ДН и КНД фазированных антенных решёток произвольной конфигурации. Реализован расчёт множителя решётки для четырёх типов АР: линейной эквидистантной, линейной с произвольным расположением элементов, плоской и пространственной (объёмной) с произвольным расположением элементов. Параметры решётки задаются в формате CSV (2, 3 или 4 колонки для 1D, 2D и 3D соответственно).

2. Расчёт пространственной (3D) АР реализован на основе формулы 12.9 [1] с обобщением на произвольное расположение элементов. Верификация подтвердила вырождение 3D формулы в 2D при $z_n = 0$ с точностью $\sim 10^{-12}$, а также корректность расчёта КНД для кубоидных решёток.

3. Верификация на аналитических тестах показала совпадение результатов с машинной точностью ($\sim 10^{-15}$) для множителя решётки и точное совпадение КНД ($D_0 = N$) для эквидистантных решёток с $d = \lambda/2$.

4. Сравнительное тестирование четырёх подходов к реализации (Pure Python, NumPy, C++ + NumPy, Pure C++) показало, что **наибольшую производительность обеспечивает векторизованная реализация на NumPy** — ускорение до 12,8× по сравнению с чистым Python и до 3,4× по сравнению с чистым C++. Превосходство NumPy обусловлено использованием оптимизированных библиотек линейной алгебры (BLAS) с SIMD-инструкциями процессора, которые обеспечивают параллельную обработку массивов.

5. Чистый C++ пайплайн (`FullPipeline1D`/`2D`/`3D`) оказался в 1,5–2,3 раза быстрее гибридного подхода (C++ + NumPy), что подтвердило значительность накладных расходов на маршалинг данных через интерфейс ctypes.

6. По результатам бенчмарков расчёт ДН в модулях `calc_2d.py` и `calc_3d.py` переведён на NumPy. Корректность NumPy-реализации подтверждена совпадением с результатами C++ с точностью $\sim 10^{-15}$. C++ библиотека сохранена для бенчмарков и для операций с нестандартными структурами данных (извлечение модуля из `complex_t` — ускорение 29×).
