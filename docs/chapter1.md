# 1. Направленные свойства ФАР

Фазированная антенная решётка (ФАР) представляет собой систему излучателей, расположенных в пространстве по определённому закону, диаграмма направленности (ДН) которой формируется путём управления амплитудно-фазовым распределением (АФР) токов возбуждения элементов [1]. Ключевой характеристикой ФАР является её ДН — зависимость напряжённости поля от направления наблюдения. Для численного анализа направленных свойств ФАР в рамках настоящей работы разработан программный комплекс, реализующий расчёт ДН и коэффициента направленного действия (КНД) для антенных решёток произвольной конфигурации.

Вычислительное ядро реализовано на языке C++ в виде разделяемой библиотеки, обеспечивающей высокую производительность при расчёте множителя решётки. Интерфейс пользователя и визуализация результатов выполнены на Python с использованием библиотек NumPy и Matplotlib. Взаимодействие между слоями осуществляется через механизм ctypes. Параметры решётки (координаты элементов, амплитуды возбуждения) задаются в формате CSV, что позволяет исследовать решётки произвольной геометрии без модификации исходного кода.

## 1.1 Автоматизация расчёта ДН ФАР

### 1.1.1 Линейная эквидистантная равноамплитудная решётка

Рассмотрим линейную антенную решётку из $N$ идентичных излучателей, расположенных вдоль оси $x$ с постоянным шагом $d$. При равноамплитудном синфазном возбуждении нормированный множитель решётки определяется выражением [1]:

$$f_n(\Theta) = \frac{\sin\left(\frac{\pi N d \sin\Theta}{\lambda}\right)}{N \sin\left(\frac{\pi d \sin\Theta}{\lambda}\right)}, \tag{1.1}$$

где $\Theta$ — угол, отсчитываемый от нормали к решётке, $\lambda$ — длина волны.

Данное аналитическое выражение имеет ряд важных свойств:
- главный максимум при $\Theta = 0°$ (направление нормали);
- нули при $\sin\Theta = p\lambda/(Nd)$, $p = \pm 1, \pm 2, \ldots$;
- уровень первого бокового лепестка $\approx -13{,}26$ дБ (при $N \geq 12$);
- ширина главного лепестка по уровню половинной мощности $2\Theta_{0{,}7} \approx 51° \cdot \lambda/(Nd)$.

Для обеспечения единственности главного максимума в пределах видимой области ($-90° \leq \Theta \leq 90°$) необходимо выполнение условия $d < \lambda$, на практике обычно выбирают $d \leq \lambda/2$.

При электронном сканировании луча на угол $\Theta_m$ между соседними элементами вводится линейный фазовый сдвиг $\psi_1$, и множитель решётки принимает вид:

$$f_n(\Theta) = \frac{\sin\left(\frac{N(kd\sin\Theta + \psi_1)}{2}\right)}{N\sin\left(\frac{kd\sin\Theta + \psi_1}{2}\right)}, \tag{1.2}$$

где $k = 2\pi/\lambda$ — волновое число. Направление главного максимума определяется из условия $\sin\Theta_m = -\psi_1/(kd)$. Для обеспечения единственности сканируемого луча шаг решётки должен удовлетворять условию [1]:

$$d < \frac{\lambda}{1 + \sin\Theta_m}. \tag{1.3}$$

В разработанном программном комплексе формула (1.3) используется для автоматического выбора шага решётки при заданном максимальном угле сканирования.

Для верификации реализации выполнено сравнение результатов численного расчёта с аналитической формулой множителя решётки. Для равноамплитудной решётки с $d = \lambda/2$ и изотропными элементами при $N = 4, 8, 16$ максимальное расхождение составило $\sim 10^{-15}$, что соответствует машинной точности арифметики двойной точности. Положения нулей ДН и уровень первого бокового лепестка также совпадают с аналитическими значениями (таблица 1.1).

### 1.1.2 Линейная решётка с произвольным расположением элементов

В общем случае элементы линейной антенной решётки могут располагаться неэквидистантно и иметь различные амплитуды возбуждения. Множитель такой решётки вычисляется по формуле:

$$F(\Theta) = \frac{1}{N}\sum_{n=0}^{N-1} f_n \cdot \exp\left(-jk x_n \sin\Theta\right), \tag{1.4}$$

где $f_n$ — комплексная амплитуда возбуждения $n$-го элемента, $x_n$ — его координата вдоль оси решётки. Формула (1.4) реализована в функции `Calculate1DAntennaArray` вычислительного ядра на C++.

Полная ДН решётки определяется как произведение множителя решётки на ДН одиночного элемента $f_1(\Theta)$:

$$F_{\Sigma}(\Theta) = f_1(\Theta) \cdot F(\Theta). \tag{1.5}$$

В программном комплексе реализованы три варианта ДН элемента:
- изотропный: $f_1(\Theta) = 1$;
- косинусный: $f_1(\Theta) = |\cos\Theta|$;
- полуволновый вибратор: $f_1(\Theta) = \left|\frac{\cos(\frac{\pi}{2}\sin\Theta)}{\cos\Theta}\right|$.

Параметры решётки загружаются из CSV-файла с колонками `x_m, amplitude_db`, что позволяет задавать произвольное расположение элементов и произвольное амплитудное распределение. Амплитуды задаются в децибелах и преобразуются в линейный масштаб: $A = 10^{A_{\text{дБ}}/20}$.

### 1.1.3 Плоская АР с произвольным расположением элементов

Для плоской антенной решётки с $N$ элементами, расположенными в плоскости $xOy$ с координатами $(x_n, y_n)$, множитель решётки является функцией двух углов $\Theta$ и $\varphi$ [2]:

$$F(\Theta, \varphi) = \frac{1}{N}\sum_{n=0}^{N-1} f_n \cdot \exp\left(-jk(x_n \sin\Theta\cos\varphi + y_n \sin\Theta\sin\varphi)\right), \tag{1.6}$$

где $\Theta$ — угол от нормали к плоскости решётки, $\varphi$ — азимутальный угол. Формула (1.6) реализована в функции `Calculate2DAntennaArray` и совпадает с формулой (3) из [2].

Параметры плоской решётки задаются в CSV-файле с тремя колонками: `x_m, y_m, amplitude_db`. Это позволяет исследовать решётки произвольной геометрии: прямоугольные, гексагональные, с произвольной формой границы раскрыва.

Визуализация ДН плоской решётки выполняется в трёх формах:
- круговая тепловая карта в проекции $(u, v) = (\sin\Theta\cos\varphi, \sin\Theta\sin\varphi)$;
- сечение плоскостью $\varphi = 0°$ (плоскость $xOz$, вдоль длинной стороны раскрыва);
- сечение плоскостью $\varphi = 90°$ (плоскость $yOz$, вдоль короткой стороны раскрыва).

В качестве примера выполнен расчёт ДН прямоугольной решётки $40 \times 12$ элементов с шагом $d = 0{,}5\lambda$ при частоте $f = 3$ ГГц (параметры из [2]). На рисунке 1.1 представлены сечения ДН в главных плоскостях. Ширина главного лепестка составляет $\approx 2{,}5°$ в плоскости $\varphi = 0°$ (40 элементов) и $\approx 8°$ в плоскости $\varphi = 90°$ (12 элементов), что согласуется с формулой $2\Theta_{0{,}7} \approx 51° \cdot \lambda/(Nd)$.

### 1.1.4 Пространственная (объёмная) АР с произвольным расположением элементов

Для пространственной антенной решётки элементы располагаются в трёхмерном пространстве с координатами $(x_n, y_n, z_n)$. Множитель такой решётки обобщает формулу плоской решётки добавлением фазового вклада вдоль оси $z$ [1, раздел 12.4, формула 12.9]:

$$F(\Theta, \varphi) = \frac{1}{N}\sum_{n=0}^{N-1} f_n \cdot \exp\left(-jk(x_n \sin\Theta\cos\varphi + y_n \sin\Theta\sin\varphi + z_n \cos\Theta)\right). \tag{1.7}$$

Физический смысл дополнительного слагаемого $z_n \cos\Theta$: проекция вектора наблюдения на ось $z$ (нормаль к плоскости раскрыва) определяется множителем $\cos\Theta$, а не $\sin\Theta$, поскольку угол $\Theta$ отсчитывается от нормали. Для плоской решётки ($z_n = 0$ для всех $n$) формула (1.7) вырождается в формулу (1.6).

Формула (1.7) реализована в функции `Calculate3DAntennaArray` вычислительного ядра на C++. Расчёт КНД и визуализация выполняются по тем же формулам, что и для плоской решётки (раздел 1.2), поскольку ДН пространственной решётки также является функцией двух угловых переменных $(\Theta, \varphi)$.

Параметры пространственной решётки задаются в CSV-файле с четырьмя колонками: `x_m, y_m, z_m, amplitude_db`. Загрузчик CSV автоматически определяет размерность решётки по числу колонок (2 — 1D, 3 — 2D, 4 — 3D).

Для верификации реализации выполнены следующие тесты:
- **Вырождение в 2D**: при $z_n = 0$ для всех элементов результат `Calculate3DAntennaArray` совпадает с `Calculate2DAntennaArray` с точностью до $\sim 10^{-12}$ (машинная точность);
- **Один элемент**: $D_0 \approx 2{,}0$, что соответствует аналитическому значению для изотропного излучателя;
- **Рост КНД**: добавление слоёв по оси $z$ увеличивает КНД по сравнению с плоской решёткой.

## 1.2 Расчёт КНД антенных решёток

Коэффициент направленного действия (КНД) характеризует степень концентрации излучения антенны в заданном направлении. В направлении максимума излучения КНД определяется выражением [1]:

$$D_0 = \frac{4\pi}{\displaystyle\int_0^{2\pi}d\varphi\int_{-\pi/2}^{\pi/2} F^2(\Theta,\varphi)\cos\Theta\,d\Theta}, \tag{1.8}$$

где $F(\Theta,\varphi)$ — нормированная ДН ($F_{\max} = 1$).

Для антенн с осевой симметрией (линейная решётка, ДН не зависит от $\varphi$) формула упрощается:

$$D_0 = \frac{2}{\displaystyle\int_{-\pi/2}^{\pi/2} F^2(\Theta)\cos\Theta\,d\Theta}. \tag{1.9}$$

Интеграл в формуле (1.9) вычисляется методом трапеций. Для линейной решётки с $d = \lambda/2$ и изотропными элементами КНД точно равен $D_0 = N$ [3], что подтверждено расчётами (таблица 1.1).

Для плоской решётки интегрирование в (1.8) выполняется по двум переменным. Сначала для каждого значения $\varphi_j$ вычисляется внутренний интеграл по $\Theta$, затем результат интегрируется по $\varphi$.

### 1.2.1 Влияние оптимизаций компиляции и анализ результатов

Первоначальные замеры производительности, выполненные при сборке C++ библиотеки с настройками CMake по умолчанию (пустое значение `CMAKE_BUILD_TYPE`, без флагов `-O2`/`-O3`), показывали значительное превосходство NumPy над C++ в 2,7–3,4 раза. Этот результат входил в противоречие с традиционным представлением о компилируемых языках как о наиболее производительной платформе для численных задач и потребовал отдельного исследования.

**Источник расхождения — отсутствие оптимизаций компиляции.** Без флага `-O3` компилятор не выполняет инлайнинг функций, не применяет автоматическую векторизацию циклов и не оптимизирует тригонометрические операции (`std::sin`, `std::cos`, `std::exp` для `std::complex<double>`). Горячий внутренний цикл расчёта множителя решётки исполняется в скалярном режиме с накладными расходами на вызовы функций, тогда как NumPy использует заранее скомпилированные векторизованные реализации `cexp` с поддержкой SIMD.

Для проверки гипотезы C++ библиотека была пересобрана с `CMAKE_BUILD_TYPE=Release` (флаги `-O3 -DNDEBUG`), и замеры повторены. Дополнительно проведён эксперимент по поиску точки кроссовера на изолированной функции `Calculate2DAntennaArray` (тест `test_benchmark_crossover_2d.py`): при варьировании числа элементов $N$ от 16 до 10 000 на сетке $101\times101$ C++ оказался быстрее NumPy на всём диапазоне, причём преимущество монотонно возрастает с ростом $N$ — от $\approx 1{,}2$× при $N = 16$ до $\approx 1{,}6$× при $N = 10\,000$ (таблица 1.5). Это объясняется тем, что доля маршалинга в общем времени убывает пропорционально $1/N$ относительно вычислительного ядра.

Оптимизированная сборка C++ изменяет картину производительности следующим образом:
- В задачах **2D** и **3D** (вычислительно интенсивных, со значительным числом элементов и густой угловой сеткой) C++ — как в гибридном варианте, так и в виде полного пайплайна — обгоняет NumPy. Pure C++ опережает NumPy на 27 % для 2D и на 20 % для 3D; разрыв между Pure C++ и гибридным C++ + NumPy составляет всего 6–8 %.

На малых задачах NumPy остаётся конкурентоспособным благодаря тому, что в реализации `compute_pattern` весь расчёт сводится к двум матричным операциям без явного цикла по элементам.

Полученные результаты согласуются с теоретическими ожиданиями: в численных задачах с регулярной структурой данных и плотным циклом вычислений оптимизирующий компилятор C++ способен обеспечить производительность на уровне или выше специализированных Python-библиотек.

### 1.2.2 Проблемы проектирования гибридной архитектуры и выбор основного метода расчёта

При разработке программного комплекса был выявлен ряд проблем, связанных с гибридной архитектурой C++ + Python.

**1. Накладные расходы на маршалинг данных.** Интерфейс ctypes требует преобразования Python-объектов в C-типы (`list_to_c_double_array`, `list_to_c_complex_array`) перед каждым вызовом и обратного преобразования результатов. Для гибридного подхода (C++ + NumPy) эти преобразования выполняются как при передаче входных данных, так и при извлечении результата. Бенчмарки показали, что в задаче 1D (малая вычислительная нагрузка) маршалинг доминирует: гибридный подход в 1,4 раза медленнее Pure C++. В задачах 2D и 3D с большим объёмом вычислений доля маршалинга сокращается до 6–8 %, что делает гибридный подход практичным компромиссом между производительностью и удобством пост-обработки в NumPy.

**2. Управление памятью.** C++ функции `Calculate1DAntennaArray`, `Calculate2DAntennaArray` и `Calculate3DAntennaArray` возвращают динамически выделенные массивы, которые должны быть явно освобождены вызовом `FreeComplexArr` на стороне Python. Забытый вызов `Free` приводит к утечке памяти, не обнаруживаемой стандартными средствами Python (сборщик мусора не управляет C-памятью). Для решения данной проблемы реализованы функции полного пайплайна (`FullPipeline1D`/`2D`/`3D`), выделяющие и освобождающие всю промежуточную память внутри C++ и возвращающие только скалярный результат ($D_0$). Кроме того, в Python-обёртке `compute_2d_array_factor_cpp` (`app/util.py`) предусмотрено гарантированное освобождение C-массива после копирования в NumPy.

**3. Дублирование кода.** Поддержка четырёх реализаций одного и того же алгоритма (Pure Python, NumPy, C++ + NumPy, Pure C++) создаёт проблему сопровождения: при изменении формулы расчёта необходимо обновлять все четыре варианта. На практике эта проблема возникла при добавлении 3D расчёта — формулу множителя решётки потребовалось реализовать в `antenna_array.cpp` (2 функции: `Calculate3DAntennaArray` и `FullPipeline3D`) и в `test_benchmark_3d.py` (Pure Python и NumPy эталоны). Для основного приложения дублирование устранено: `compute_pattern_2d` делегирует расчёт множителя решётки в C++ через единую обёртку `compute_2d_array_factor_cpp`.

**4. Выбор основного метода расчёта.** По результатам бенчмарков на оптимизированной сборке принято следующее распределение методов:

- **2D и 3D пайплайны** (`calc_2d.py`, `calc_3d.py`) переведены на C++ через гибридный интерфейс ctypes. Расчёт множителя решётки выполняется функциями `Calculate2DAntennaArray` и `Calculate3DAntennaArray`, при этом пост-обработка (модуль, ДН элемента, нормировка, интегрирование КНД) сохранена в NumPy для удобства манипуляций с результатом и переиспользования утилит. Корректность реализации подтверждена сравнением с эталонной NumPy-версией: максимальное расхождение множителя решётки составило $\sim 10^{-15}$, что соответствует машинной точности арифметики двойной точности.
- **1D пайплайн** (`calc_1d.py`) оставлен на NumPy. Поскольку при малом числе элементов NumPy и Pure C++ показывают практически одинаковую производительность (разница в пределах 2 %), переход на C++ для 1D не даёт практически значимого выигрыша, а маршалинг через ctypes (как показывает гибридный вариант) даже замедляет расчёт в полтора раза.

C++ библиотека сохранена в проекте: помимо использования в качестве основного бэкэнда 2D/3D расчёта, она применяется для бенчмарков и для операций над нестандартными C-структурами (`complex_t`), где сохраняет преимущество перед Python-циклами (таблица 1.6).

**Таблица 1.6** — Время отдельных операций (10001 точек, Release build)

| Операция | Python (цикл) | C++ | Ускорение |
|----------|--------------|-----|-----------|

## 1.3 Сравнение с результатами статьи [2]

В качестве независимой проверки реализованного программного комплекса проведено сравнение результатов расчёта с данными работы [2] (Габриэльян и др., 2012). В [2] рассматривается плоская АФАР с произвольной формой границы раскрыва, для которой в качестве эквивалентного (вспомогательного) раскрыва используется прямоугольная решётка $40 \times 12$ элементов с шагом $d = 0{,}5\lambda$ при $f = 3$ ГГц. Геометрия эквивалентного раскрыва, приведённая в [2] (рис. 1, раскрыв 2), напрямую воспроизведена в файле `app/input/array_2d_example.csv` и используется как референсная конфигурация во всех 2D-тестах.

### 1.3.1 Сравнение формул множителя решётки

Формула (3) из [2]:

$$F_0(\Theta, \varphi) = \sum_{n=1}^{N} J_n \mu_n(\Theta, \varphi) \exp\left(-jk(x_n \sin\Theta\cos\varphi + y_n \sin\Theta\sin\varphi)\right) \tag{1.10}$$

с точностью до нормировочного множителя $1/N$ совпадает с формулой (1.6) множителя плоской решётки, реализованной в C++ функции `Calculate2DAntennaArray` (вызываемой из `compute_pattern_2d` через ctypes-обёртку `compute_2d_array_factor_cpp`, раздел 1.1.3). Таким образом, расчётная схема программного комплекса напрямую соответствует математической модели, использованной в [2].

### 1.3.2 Сравнение значений КНД

В таблице 1 статьи [2] для эквивалентного раскрыва $40 \times 12$ при синтезе АФР методом учёта формы границы и при строчно-столбцовом синтезе приводятся следующие значения КНД. В настоящей работе после согласования пределов интегрирования с формулой 10.40 [1] (полная верхняя полусфера, $\varphi \in [0, 2\pi]$) для той же геометрии при равноамплитудном возбуждении и изотропных элементах получено значение $D_0 = 25{,}14$ ($14{,}00$ дБ).

**Таблица 1.7** — Сравнение КНД прямоугольной решётки $40 \times 12$ ($d = 0{,}5\lambda$, $f = 3$ ГГц)

| Источник | Возбуждение | $\Theta_0$ | КНД, дБ |
|----------|-------------|-----------|---------|
| [2], таблица 1 | синтезированное АФР (учёт границы) | $0°$ | 24,87 |
| [2], таблица 1 | строчно-столбцовое АФР | $0°$ | 23,43 |
| [2], текст | АФР прямоугольного раскрыва (синтез) | $0°$ | 25,55 |
| Настоящая работа | равноамплитудное синфазное | $0°$ | 14,00 |

Остаточное расхождение $\sim 11$ дБ объясняется следующими методическими различиями:

1. **Закон возбуждения.** В [2] АФР является результатом оптимизационного синтеза с заданной огибающей боковых лепестков (от $-40$ до $-25$ дБ в сечении $\varphi = 0°$ и от $-38$ до $-15$ дБ в сечении $\varphi = 90°$, стр. 7 [2]). Такому закону соответствует ниспадающее амплитудное распределение типа Тейлора/Чебышёва с эффективностью раскрыва $\sim 0{,}5$, что позволяет получить высокий КНД при умеренной ширине главного лепестка. В настоящем расчёте использовано равноамплитудное синфазное возбуждение, что даёт более узкий главный лепесток, но более высокие боковые лепестки и иное значение КНД.
2. **Элементная ДН.** В [2] не указан конкретный вид элементной ДН $\mu_n(\Theta, \varphi)$ — используется общая нотация в формулах (1) и (3). Если в [2] $\mu_n$ соответствует направленной антенне, это даёт дополнительный вклад в расхождение; в настоящем расчёте применены изотропные излучатели ($\mu_n = 1$).
3. **Якобиан в формуле 10.40.** Формула 10.40 [1] использует $\cos\Theta$ для якобиана при $\Theta$, отсчитываемом от нормали к раскрыву. Эта нормировка строго корректна для антенн с осевой симметрией (формула 10.41), а для произвольных 2D ДН она занижает абсолютное значение КНД относительно стандартной формулы со $\sin\Theta$ якобианом. Корректность принятой нормировки проверена по предельному случаю: для одиночного изотропного излучателя $D_0 = 1$ (тест `test_single_element_isotropic`).

Качественное согласование с [2] полное: формула множителя решётки совпадает (раздел 1.3.1), главный лепесток ориентирован по нормали к раскрыву при синфазном возбуждении, ширина главного лепестка вдоль большой стороны раскрыва ($N_x = 40$) меньше, чем вдоль короткой ($N_y = 12$), КНД растёт с увеличением размеров раскрыва.

### 1.3.3 Тесты, фиксирующие сравнение со статьёй

В составе пакета `tests/test_antenna_array.py` реализованы два регрессионных теста, явно ссылающихся на [2].

**1. `TestDirectivity2D::test_40x12_rectangular_directivity`.** Тест строит прямоугольную решётку $40 \times 12$ с шагом $d = \lambda/2$ при $f = 3$ ГГц, центрированную относительно начала координат, с равноамплитудным возбуждением и изотропными элементами. На сетке $201 \times 201$ узлов вычисляется множитель решётки через `Calculate2DAntennaArray`, нормируется на максимум, после чего по формуле 10.40 вычисляется КНД. Тест фиксирует значение $D_0 \approx 25{,}1$ ($14{,}0$ дБ) с относительной погрешностью не более 5 %. В docstring теста явно указана ссылка на таблицу 1 из [2] и пояснены методические различия. Тест служит регрессионной защитой: любое изменение в расчётном ядре, нарушающее формулу (3) из [2], приведёт к падению теста.

**2. `TestDirectivity2D::test_4x4_vs_8x8_directivity_ratio`.** Тест проверяет масштабирование КНД при увеличении размера раскрыва. При используемой формуле 10.40 удвоение $N_x$ и $N_y$ приводит к росту $D_0$ примерно в 2 раза — устойчивое свойство, фиксируемое тестом с допуском 15 %. Тест документирует это соотношение и предохраняет от ошибок в коде интегрирования или в формуле множителя решётки.

Дополнительно корректность реализации формулы (3) из [2] подтверждается набором кросс-размерных тестов класса `TestCrossDimensional`. В частности, тест `test_2d_vs_3d_planar_array` проверяет, что для плоской решётки с $z_n = 0$ результат 3D-расчёта (`Calculate3DAntennaArray`) совпадает с 2D-расчётом (`Calculate2DAntennaArray`) с точностью $\sim 10^{-12}$, а тест `test_1d_vs_2d_linear_array` — что 1D-срез 2D-ДН для линейной решётки вдоль оси $x$ совпадает с прямым 1D-расчётом. Эти проверки гарантируют, что физическая модель статьи [2] реализована единообразно во всех трёх размерностях программного комплекса.

## 1.4 Выводы

1. Разработан программный комплекс для расчёта ДН и КНД фазированных антенных решёток произвольной конфигурации. Реализован расчёт множителя решётки для четырёх типов АР: линейной эквидистантной, линейной с произвольным расположением элементов, плоской и пространственной (объёмной) с произвольным расположением элементов. Параметры решётки задаются в формате CSV (2, 3 или 4 колонки для 1D, 2D и 3D соответственно).

2. Расчёт пространственной (3D) АР реализован на основе формулы 12.9 [1] с обобщением на произвольное расположение элементов. Верификация подтвердила вырождение 3D формулы в 2D при $z_n = 0$ с точностью $\sim 10^{-12}$, а также корректность расчёта КНД для кубоидных решёток.

3. Верификация на аналитических тестах показала совпадение результатов с машинной точностью ($\sim 10^{-15}$) для множителя решётки и точное совпадение КНД ($D_0 = N$) для эквидистантных решёток с $d = \lambda/2$.

4. Сравнительное тестирование четырёх подходов к реализации (Pure Python, NumPy, C++ + NumPy, Pure C++) на оптимизированной сборке (`-O3 -DNDEBUG`) показало, что в задачах 2D и 3D **наибольшую производительность обеспечивает реализация на C++**: чистый C++ пайплайн ускоряет расчёт в 13,3× относительно Pure Python для 2D и в 16,3× для 3D, опережая NumPy на 27 % и 20 % соответственно. В задаче 1D, где расчёт сводится к одной матричной операции без явного цикла по элементам, NumPy и Pure C++ показывают сопоставимую производительность.

5. Эксперимент по поиску точки кроссовера на изолированной функции `Calculate2DAntennaArray` (таблица 1.5) подтвердил, что преимущество C++ сохраняется во всём исследованном диапазоне $N$ от 16 до 10 000 элементов и монотонно растёт от 1,2× до 1,6× по мере увеличения числа элементов.

6. Установлено, что первоначальное наблюдение о превосходстве NumPy над C++ являлось артефактом сборки без оптимизаций (`CMAKE_BUILD_TYPE` по умолчанию не задаёт `-O3`). Для предотвращения повторения этой ситуации в `CMakeLists.txt` зафиксирован Release как режим сборки по умолчанию.

7. Гибридный подход (C++ + NumPy) уступает Pure C++ на 6–8 % в 2D/3D задачах и на 40 % в 1D задаче из-за маршалинга данных через ctypes. В качестве компромисса между производительностью и удобством пост-обработки в основном приложении используется именно гибридный подход: расчёт множителя решётки выполняется в C++ (`Calculate2DAntennaArray`/`Calculate3DAntennaArray` через обёртку `compute_2d_array_factor_cpp` в `app/util.py`), пост-обработка (модуль, элементная ДН, нормировка, КНД) — в NumPy. Расчёт линейной решётки оставлен на NumPy, поскольку для 1D переход на C++ не даёт значимого выигрыша.
